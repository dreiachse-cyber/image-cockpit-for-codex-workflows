# v0.1.8 Release Notes

Status: release candidate awaiting owner review
Target: safer and faster Animation Generation after v0.1.7

Image Cockpit for Codex Workflows v0.1.8 combines the restored-queue safety fix with parallel direction generation, exclusive three-runner admission, failed-direction-only retry, and a stricter First Qualified Wins path for Best tournaments.

## Highlights

### First Qualified Wins

- Best still starts candidates A/B/C together.
- When exactly one candidate has completed and both remaining candidates are still running, the first candidate may win immediately through a strict solo gate.
- The strict solo gate requires every requested direction to be verified, zero quality warnings, a score of at least 3300, an identity score of at least 85, and `shadowWouldBlock: false`.
- If the first candidate does not pass the strict solo gate, Image Cockpit waits for the second terminal candidate and uses the existing two-candidate Smart Race.
- If the two-candidate comparison is not decisive, Image Cockpit waits for all three candidates and performs the full comparison.
- Winner publication and loser cancellation remain protected by the tournament lock, and the server independently revalidates the persisted candidate metrics before accepting a First Qualified decision.
- If another candidate becomes terminal before the server accepts the decision, First Qualified is rejected and the tournament safely falls back to comparison.

### Faster direction generation and targeted retry

- Each animation candidate can submit every requested direction to built-in image generation concurrently.
- A five-direction Best tournament can therefore run up to five direction generations per candidate across three candidates, while the visible UI remains an A/B/C tournament.
- Capacity-aware wave sizing can shrink from five or four directions to three, then one, without creating extra Codex candidate jobs.
- Directions that already passed are frozen, and only failed directions are regenerated.
- Smart Race can still accept a clear safe winner after two candidates when the strict one-candidate gate does not pass.

### Queue and admission safety

- Restored queued tournaments are monitor-only and do not automatically start after reload.
- Only tournaments explicitly registered in the current session may start their initial candidate wave or an adaptive Balanced candidate.
- Concurrent semantic duplicates with different random tournament IDs resolve to one canonical unfinished tournament.
- A synchronous Generate lock prevents double-click registration races.
- Animation Generation requires the global three-runner pool to be completely idle before its fixed initial wave starts.
- The server admits the initial wave atomically and rejects generic-job or individual-candidate bypasses.

## Performance guidance

- First Qualified Wins reduces user-visible completion time only when the first completed candidate clears the strict gate.
- Because all three candidates start together, some initial direction-generation work may already be in flight when a winner is accepted.
- The largest savings come from cancelling later candidate processing and avoiding additional direction retry waves.
- Completion time, generated-image usage, and retries still depend on the local Codex/imagegen environment and model-side behavior.

## Local-First Boundary

The app still does not call OpenAI APIs directly and does not require an API key. It writes local handoff files for Codex, the user, or another local workflow to process.

No model weights, API keys, tokens, generated handoff folders, or license-unclear sample assets are included in the repository.

## Known Limitations

- The strict solo gate treats every current warning as unsafe because the existing candidate warning count does not expose severity classes.
- The real charged maximum-15-imagegen path and a live First Qualified cancellation run remain owner-gated and are not required for the local release-candidate verification.
- In-flight image-generation calls may finish after loser cancellation has been requested.
- Generated image quality and completion time remain dependent on the available local generation environment.
