# v0.1.7bugfix Release Notes

Status: maintenance update for the v0.1.7 code line
Release label: `v0.1.7bugfix`
Package, App, and API version: `0.1.7`

Image Cockpit for Codex Workflows v0.1.7bugfix prevents restored Animation Generation tournaments from starting new image-generation work without a current user action.

This maintenance label intentionally keeps the SemVer-compatible package, App, and API version at `0.1.7`. This document does not create a Git tag or GitHub Release.

## Fixed

### Restored tournament auto-start

- Restored server-side tournaments remain visible in the monitor after a page reload, but jobless queued candidates are display-only.
- Only a tournament explicitly registered by Generate or a confirmed Batch Matrix action in the current UI session may start initial candidates.
- The same current-session authorization is required before a Balanced tournament may start its adaptive candidate C.
- Existing running jobs can still be monitored and evaluated without granting permission to start additional image-generation jobs.

### Duplicate registration races

- Generate now uses a synchronous in-flight guard so repeated clicks cannot submit multiple registrations before React updates the busy state.
- The server computes a stable semantic key from the source fingerprint, Motion Recipe, preset, profile, directions, candidate counts, pilot settings, and normalized job contract.
- Concurrent unfinished registrations with different random tournament IDs but the same semantic request collapse to one canonical tournament under a process-wide registration lock.
- An explicit Generate action accepts the canonical tournament returned by the server, so safe deduplication does not block the requested run.
- A stale manifest marked running is refreshed before reuse; if its runner is already terminal, a new registration is allowed.
- Motion Pilot fallback records the canonical fallback tournament ID when an equivalent unfinished fallback already exists.

## User impact

- Reloading Image Cockpit no longer drains old queued animation requests automatically.
- Repeated clicks or repeated equivalent registration calls no longer multiply the number of unfinished tournaments.
- Different frame contracts or other meaningful generation-setting changes still create separate tournaments.
- Cancelling or completing the canonical tournament allows a later equivalent request to create a new run.
